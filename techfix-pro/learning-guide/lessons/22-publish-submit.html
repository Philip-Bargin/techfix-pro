Lesson 22 · Polish, Publish & Submit

Publish on GitHub Pages & Submit in Google Classroom

Your website works on your computer. Now you'll put it on the internet so anyone, including your teacher, can open it with a link. You'll upload your project to GitHub, switch on GitHub Pages to get a free public web address, and submit that address in Google Classroom.

  • About 30–45 minutes
  • Needs an internet connection
  • Uploads: your whole techfix-pro folder

By the end of this lesson you will be able to

  • Create a free GitHub account and a public repository.
  • Upload your website files to GitHub using only your web browser.
  • Turn on GitHub Pages and get a public link that opens your index.html.
  • Test the link and fix common publishing problems.
  • Submit the link through Google Classroom and confirm it was turned in.

New terms

GitHub: a free website where people store and share code projects.
Repository (“repo”): a project folder stored on GitHub.
Commit: saving a set of changes to a repository, with a short message describing them.
GitHub Pages: a free GitHub feature that turns a repository of HTML and CSS files into a real, public website.
URL: a web address, like https://example.com/.

Before you start

  • Finish the final project checklist. Every page should work on your computer first.
  • Know where your project is: Documents/my-websites/techfix-pro.
  • Check that every file and folder name is lowercase with no spaces. Online, About.html and about.html are different files, so a link that works on your computer can break on the internet (see “Fix problems” in Part C).

Part A — Upload your project to GitHub

Create a free GitHub account

  1. Go to github.com/signup.
  2. Enter your email address (use your school email if your teacher asks you to), create a password, and choose a username.
  3. Complete the puzzle that checks you're a person, then enter the code GitHub emails you.
  4. If GitHub asks questions about how you'll use it, you can skip them or choose the free plan.

Choose your username carefully

Your username becomes part of your website's address: https://your-username.github.io/…. Keep it simple and appropriate, for example maria-santos-dev. Write it down, because you'll need it later.

Create a new repository

  1. Sign in to GitHub. Click the + button at the top-right of the page and choose New repository.
  2. In Repository name, type techfix-pro (lowercase, with a hyphen).
  3. Choose Public. GitHub Pages is free only for public repositories, and your teacher must be able to open the site.
  4. Leave the other options (README, .gitignore, license) unticked / set to “None”.
  5. Click the green Create repository button.

Open the upload page

Your new, empty repository opens with a Quick setup box. Inside it, find the sentence that says “…or create a new file or upload an existing file”, and click uploading an existing file.

(If your repository already has files in it, click Add file → Upload files near the top of the file list instead.)

Drag in your website files

This is the most important step. You must upload the contents of your techfix-pro folder, not the folder itself, so that index.html ends up at the top level of the repository.

  1. Open your Documents/my-websites/techfix-pro folder in File Explorer (Windows) or Finder (Mac).
  2. Click inside the folder and press Ctrl + A (Cmd + A on Mac) to select everything inside it: the six .html files, styles.css and the images folder.
  3. Drag the selected items onto the upload area of the GitHub page (it says “Drag files here…”). Dragging is the only way to upload a folder like images; the “choose your files” button can only pick single files.
  4. Wait until every file appears in the list below the upload area.
✅ Correct: files at the top level❌ Wrong: everything inside a folder
techfix-pro (repository) ├── index.html ├── about.html ├── services.html ├── blog.html ├── gallery.html ├── contact.html ├── styles.css └── images/
techfix-pro (repository) └── techfix-pro/ ← extra folder! ├── index.html ├── about.html └── …

Your site would be at a longer, unexpected address, and the main link would show a 404 error.

Empty folders are skipped

GitHub doesn't upload empty folders. If your images folder is empty (you skipped Lesson 19), that's fine: it simply won't appear. If you did use local images, make sure the images folder shows up in the upload list.

Commit the upload

  1. Scroll down to Commit changes.
  2. In the first box, type a short message such as Upload TechFix Pro website.
  3. Leave Commit directly to the main branch selected.
  4. Click the green Commit changes button and wait a few seconds.

You'll return to your repository's main page. Check that the file list looks like the correct example above, with index.html visible straight away and not hidden inside another folder.

Part B — Turn on GitHub Pages

Open the Pages settings

  1. On your repository's page, click the Settings tab (the gear icon in the row of tabs near the top). If you can't see it, click the … menu at the end of the tabs.
  2. In the left-hand menu, under Code and automation, click Pages.

Publish from the main branch

  1. Under Build and deployment, set Source to Deploy from a branch.
  2. Under Branch, open the first dropdown (it may say None) and choose main.
  3. Leave the second dropdown on / (root), which means “the top level of the repository”, where your index.html is.
  4. Click Save.

Wait for your site to go live

GitHub now builds your website. This usually takes 1–3 minutes.

  1. Wait a minute, then refresh the Pages settings page (F5).
  2. When it's ready, a box at the top says “Your site is live at …” with a Visit site button.
  3. Click Visit site. Your TechFix Pro Home page opens on the real internet! 🎉
Your site is live at https://your-username.github.io/techfix-pro/   Visit site

Still not there after 5 minutes? Click the repository's Actions tab. A job called pages build and deployment shows a yellow dot while working, a green tick when finished, or a red cross if something went wrong.

Part C — Your public link

Your website's address always follows this pattern:

https://secure web addressyour-usernameyour GitHub username.github.io/GitHub Pagestechfix-proyour repository name/opens index.html

When a web address ends with a folder name and a /, the server automatically shows the index.html file inside it (remember Lesson 4?). So these two links open exactly the same page, your Home page:

  • https://your-username.github.io/techfix-pro/
  • https://your-username.github.io/techfix-pro/index.html

Your other pages are at the same address with their file names added, for example …/techfix-pro/about.html.

Submit the right link

The link you submit must contain .github.io. Do not submit the repository link (https://github.com/your-username/techfix-pro), because that shows your files, not your website. Only share your repository link if your teacher asks for it separately.

Test your link properly

Copy the address from your browser's address bar after clicking Visit site. Then test it the way your teacher will see it:

  1. Open a private / incognito window (Ctrl + Shift + N in Chrome and Edge, Ctrl + Shift + P in Firefox), paste the link and press Enter.
  2. Click every navbar link, the Media dropdown links, the buttons and the footer links. Every page should open.
  3. Check that all images, icons and fonts appear.
  4. Open the link on a phone and try the ☰ menu.

Update your site after changes

Made a fix in VS Code? Upload the changed file again:

  1. In your repository, click Add file → Upload files.
  2. Drag in the changed file(s). A file with the same name replaces the old one.
  3. Write a commit message (e.g. Fix About link) and click Commit changes.
  4. Wait 1–2 minutes, then reload your website with Ctrl + Shift + R to see the update. Your link stays the same, so you don't need to resubmit it.

Part D — Submit your link in Google Classroom

Open the assignment

  1. Go to classroom.google.com and sign in with your school Google account.
  2. Click your class card.
  3. Click the Classwork tab, then click the TechFix Pro assignment your teacher posted, then View assignment (or View instructions).
  4. Read your teacher's instructions. If they differ from this guide (for example, they ask for a different link format), follow your teacher.

Attach your website link

  1. In the Your work box, click + Add or create.
  2. Choose Link.
  3. Paste your GitHub Pages address (the one with .github.io) and click Add link.
  4. The link now appears in the Your work box. Click it once to check that it opens your website.

Turn it in

  1. Optionally, add a private comment to your teacher (for example, anything you'd like them to look at).
  2. Click Turn in, then click Turn in again in the confirmation box.
  3. The status changes to Turned in. You're done!

Using the Classroom phone app?

Open the assignment, tap the Your work bar to expand it, tap Add attachment → Link, paste your address, then tap Turn in.

Need to change your submission?

Before the deadline, open the assignment and click Unsubmit. You can then remove the link, add the correct one and click Turn in again. If you only fixed files on GitHub, you don't need to resubmit: the same link shows your updated site.

Final submission checklist

You did it!

You built a six-page, responsive website from scratch, published it on the internet, and submitted it. Your site will stay online at your github.io address, so you can share it with family and friends and add it to a portfolio.
