Lesson 20 · Polish, Publish & Submit

Troubleshooting Guide

Something doesn't look right? You're in good company. Every developer spends a lot of time fixing small mistakes. Use this page as a checklist: find your symptom, then try the fixes in order.

  • Reference page. Come back any time.

A 5-step debugging routine

  1. Save every file. A white dot on a VS Code tab means it's unsaved. Turn on File → Auto Save.
  2. Hard-refresh the browser: Ctrl + Shift + R (Cmd + Shift + R on Mac). This ignores old cached copies.
  3. Check you're viewing the right file: your own my-websites/techfix-pro, not a copy somewhere else. Look at the address bar.
  4. Inspect it: right-click the broken element → Inspect. Is the element there? Does it have the class you expect? Are its CSS rules listed, crossed out (overridden), or marked with a ⚠ (invalid)?
  5. Go back to the lesson that built the broken section. Compare your code with the code box line by line, and your page with the screenshot.

Problems with files and the browser

SymptomLikely causeFix
The browser shows my code as plain textThe file is really name.html.txtTurn on file extensions (Windows Explorer: View → Show → File name extensions) and rename the file. Create files inside VS Code.
My changes don't show upUnsaved file, browser cache, or the wrong file openSave, hard-refresh, check the address bar.
“File not found” / 404 when clicking a linkThe href doesn't match the file nameCheck spelling and capitals: services.html ≠ Services.html ≠ service.html.
Live Server says “Open a folder”You opened a single file, not a folderFile → Open Folder, then choose techfix-pro.
Live Server opens the wrong pageA parent folder is openOpen the techfix-pro folder itself.

CSS doesn't apply

SymptomLikely causeFix
No styles at all on a pagestyles.css isn't linkedCheck <link rel="stylesheet" href="styles.css"> is in the <head>, and that the file is named exactly styles.css (with an s) in the same folder.
Shared styles work, page-specific styles don'tCSS pasted outside <style>All page CSS must sit between <style> and </style>.
One rule, or everything below a certain point, is ignoredMissing ;, } or :Check the punctuation of the rule just before the first broken one. VS Code underlines many errors in red.
A class style isn't appliedClass name mismatchHTML class="service-card" ↔ CSS .service-card. Remember the dot in CSS, and no dot in HTML.
A style is crossed out in DevToolsAnother rule wins (the cascade)Find the winning rule (it's listed above). Make yours more specific or move it later. Media queries belong at the end.
var(--primary) does nothingTypo in the variableTwo hyphens, matching spelling, defined inside :root.
Styles from a hover rule never show: hover with a spaceWrite .btn:hover with no space.

Layout problems

SymptomLikely causeFix
Cards stack in one column on desktopThe grid class is on the wrong elementThe …-grid class must be on the element that directly contains the cards.
A section appears inside another, or the footer looks indentedA missing or extra </div>Press Shift + Alt + F to re-indent; wrong nesting becomes obvious. Click an opening tag: VS Code highlights its partner.
Content hidden under the navbarThe navbar is fixed and floats over the pageThe first section needs big top padding (the hero has 120px; .page-header has 140px).
The page scrolls sideways on phonesSomething is wider than the screenCheck the viewport meta tag; look for fixed widths like width: 500px; make sure img { max-width: 100%; } exists.
A badge or label is in the wrong placeIts parent isn't positionedAn absolute element is placed relative to the nearest parent with position: relative.
A decoration made with ::before/::after is missingNo contentPseudo-elements need content: ''; (even if empty).
Layers are in the wrong orderz-index without positionz-index only works on positioned (relative/absolute/fixed/sticky), grid or flex items.

Images, icons and fonts

SymptomLikely causeFix
Broken image iconWrong path or offlineCheck the address letter by letter. For local files, check the folder, the extension (.jpg/.jpeg/.png) and capitals.
Photos look squashedFixed width and height without croppingAdd object-fit: cover.
Empty squares instead of iconsFont Awesome isn't loaded, or there's a class typoCheck the Font Awesome <link> and your internet connection; use fas fa-name (two classes).
Font looks like Times New RomanGoogle Fonts link missing or font-family typoCheck the Inter <link> and font-family: 'Inter', … on body.
Background image doesn't show in the heroBad url()Use url('path') with quotes and brackets; paths in CSS are relative to the CSS file.

CSS-only interactive features

SymptomFix
☰ doesn't open the menuIn the HTML, the checkbox must come before <ul class="nav-links"> inside .nav-container. The label's for must equal the checkbox's id (menu-toggle).
A tick box is visible in the navbarMissing .menu-toggle { display: none; }.
Dropdown appears far away or vanishesNeeds .nav-links > li { position: relative; }, and the sub-menu must be inside <li class="dropdown">.
Gallery filters do nothingRadios must come before the filters and the grid, in the same parent; the ids and data-category values must match the CSS exactly.
Lightbox doesn't open, or opens the wrong photoThe photo's href="#photo-N" must match a lightbox's id="photo-N", and you need .lightbox:target { display: flex; }.
Cards don't lift on hoverMake sure .fade-in uses backwards, not both or forwards (Lesson 9).
Nothing animatesYour device may have “reduce motion” switched on, which deliberately disables the animations.

Typing mistakes to watch for

  • Curly quotes “ ” from word processors. Code needs straight quotes " ".
  • Missing closing quote: class="btn>. Everything after it becomes part of the attribute.
  • Closing tag typos: </dvi>, </secton>.
  • Self-closing confusion: <img>, <input>, <br>, <meta> and <link> have no closing tag, but <textarea>, <i> and <a> always need one.
  • Commas vs semicolons: CSS declarations end with ;, while selectors in a group are separated by ,.

Free checking tools

  • W3C HTML Validator: paste your HTML and it lists every error with a line number.
  • W3C CSS Validator: the same for CSS. (It may warn about newer features like backdrop-filter. That's OK.)
  • VS Code's Problems panel (Ctrl + Shift + M) lists CSS syntax errors.

Still stuck?

Take a short break and come back. Fresh eyes spot missing brackets in seconds. If you're still stuck, delete the broken section and type it again carefully from the lesson's code box. Retyping is often faster than hunting for one missing character.
