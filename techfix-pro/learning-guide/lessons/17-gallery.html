Lesson 17 · Building the Pages

The Gallery Page: Filters & Lightbox Without JavaScript

The Gallery shows nine photos in a grid. Hovering a photo reveals its caption, filter buttons show only one category, and clicking a photo opens it full-screen in a “lightbox”. The original site uses JavaScript for this; you will build all of it with HTML and CSS alone.

  • About 75 minutes
  • The trickiest lesson. Take your time!
  • Edits: gallery.html

By the end of this lesson you will be able to

  • Build a photo grid where some photos span two columns, using aspect-ratio.
  • Reveal a caption on hover with an overlay that fades in.
  • Build filter buttons with hidden radio buttons, the :checked selector, ~, :not() and attribute selectors.
  • Build a lightbox with links and the :target selector.

Part B — Filter buttons with radio buttons

A radio button is a round option button where only one in a group can be selected at a time. That's exactly how filters behave. The plan:

  1. Four hidden radio buttons (All, Workshop, Repairs, Team) remember which filter is selected.
  2. Four visible <label>s styled as pill buttons. Clicking a label selects its radio button.
  3. CSS uses :checked to highlight the right label and hide the photos that don't match.

  • checked on the first one makes “All” selected when the page loads.
  • Each <label for="…"> is connected to the radio with the matching id.
  • The order is essential: the radios come first, then the filters, then the grid, all inside the same .container.

Reading the selectors

Take this one:

#filter-repairs:checked ~ .gallery-grid .gallery-item:not([data-category="repairs"])

PartMeaning
#filter-repairs:checked…when the “repairs” radio button is selected,
~ .gallery-grid…find the gallery grid that comes after it (a later sibling),
.gallery-item…then every photo inside it
:not([data-category="repairs"])…whose data-category is not “repairs”,
{ display: none; }…and hide it.

Square brackets [ ] make an attribute selector: [data-category="repairs"] matches elements whose attribute has that exact value. The highlight rules work the same way: “when this radio is checked, find the label whose for matches it and colour it blue.”

The radios are hidden with opacity: 0; width: 0; height: 0; rather than display: none, so keyboard users can still reach them with Tab and arrow keys.

Save, then click each filter. Only the matching photos should remain.

Part C — The lightbox with :target

When a link points to #photo-1, the browser adds #photo-1 to the end of the address and treats the element with id="photo-1" as the target. The CSS :target selector matches that element. So:

  • Each lightbox is hidden (display: none) until it becomes the target, then it's shown (.lightbox:target { display: flex; }).
  • The close button links to #close. There is no element with that id, so no lightbox is the target any more, and it hides again.

Checkpoint

Compare your page with the screenshots in this lesson. If anything looks different, go back to the step for that section and check your code against the code box, line by line.

Common mistakes

  • Filters do nothing: the radios must come before .gallery-filters and .gallery-grid, inside the same parent. Check that each id matches the selector exactly (filter-repairs, not filter-repair).
  • A filter hides everything: check the spelling of data-category values. They must exactly match the selector (repairs, lowercase).
  • The wrong photo opens: a photo's href="#photo-3" must match id="photo-3" on the right lightbox.
  • The Back button reopens a photo: that's normal. Each opened photo is added to the browser history, because the address changed.
